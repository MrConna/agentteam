## Non-Interactive Invocation Templates

pi-agent runs in non-interactive mode with `--print` (`-p`). It processes the quoted prompt and exits. All templates below assume AgentTeam has already created an isolated git worktree for write-capable roles.

### Scout

```bash
pi -p \
  --model moonshotai-cn/kimi-k2.6 \
  --tools read,grep,find,ls \
  --session-dir ".agentteam/sessions/${RUN_ID}" \
  --no-session \
  "You are a scout. Read the assigned files, map relevant code surface, and produce a compact markdown report with: relevant files, current behavior, key risks, unknowns, and suggested next agent. Do not edit files."
```

Alternative (cheaper, no thinking):
```bash
pi -p \
  --model deepseek/deepseek-v4-flash \
  --thinking off \
  --tools read,grep,find,ls \
  --session-dir ".agentteam/sessions/${RUN_ID}" \
  --no-session \
  "<scout task packet>"
```

### Scribe

```bash
pi -p \
  --model moonshotai-cn/kimi-k2.6 \
  --tools read,grep,find,ls \
  --session-dir ".agentteam/sessions/${RUN_ID}" \
  --no-session \
  "You are a scribe. Read the run artifacts and produce: summary.md, release notes draft, and memory candidates. Do not make product decisions or edit implementation."
```

### Tester

```bash
pi -p \
  --model deepseek/deepseek-v4-flash \
  --tools read,grep,find,ls,bash \
  --session-dir ".agentteam/sessions/${RUN_ID}" \
  --no-session \
  "You are a tester. Run the validation commands, summarize pass/fail status, and produce a compact test report. You may run bash commands but do not edit source files."
```

### Narrow Coder

```bash
pi -p \
  --model deepseek/deepseek-v4-pro \
  --tools read,grep,find,ls,bash,edit,write \
  --session-dir ".agentteam/sessions/${RUN_ID}" \
  "You are a narrow coder. Work only inside the declared write scope. Edit and write files as needed. Run build/tests after edits. Produce a summary of changed files and validation results."
```

**Important:** the narrow coder must only be invoked after AgentTeam creates a dedicated worktree and the human approves the write scope.

## Tool Allowlists by Role

| Role | Tools | Rationale |
|------|-------|-----------|
| Scout | `read,grep,find,ls` | Read-only exploration. No bash, no edits. |
| Scribe | `read,grep,find,ls` | Read-only summarization. No bash, no edits. |
| Tester | `read,grep,find,ls,bash` | Adds bash for build/test commands. Still no edits. |
| Narrow Coder | `read,grep,find,ls,bash,edit,write` | Full toolset, but scoped to approved worktree. |

**Note:** `grep`, `find`, and `ls` are built-in but **off by default** in pi-agent. They must be explicitly included in `--tools`. `bash`, `edit`, and `write` are also built-in but should be treated as privileged and granted only by role.

## Session-Dir Strategy

- **Per-run isolation:** use `--session-dir ".agentteam/sessions/${RUN_ID}"` for every delegated run.
- **Ephemeral by default:** add `--no-session` for scout and scribe so no session file persists for read-only work.
- **Resumable for long work:** omit `--no-session` for coder/tester runs so the session can be resumed with `pi --continue` if the process is interrupted.
- **Cleanup:** after a run is merged or abandoned, remove the session dir to avoid disk bloat:
  ```bash
  rm -rf ".agentteam/sessions/${RUN_ID}"
  ```

## Model Routing Notes: Kimi vs DeepSeek

### Verified Model Names

Short aliases like `kimi-2.6` **failed locally**. Use full `provider/model` names:

| Alias (fails) | Verified Name | Context | Thinking | Images | Best For |
|---------------|---------------|---------|----------|--------|----------|
| `kimi-2.6` | `moonshotai-cn/kimi-k2.6` | 262K | yes | yes | Scribe, context compression, docs |
| — | `moonshotai-cn/kimi-k2.5` | 262K | yes | yes | Scribe fallback |
| — | `deepseek/deepseek-v4-flash` | 1M | yes | no | Scout, tester, cheap search |
| — | `deepseek/deepseek-v4-pro` | 1M | yes | no | Narrow coder, simple implementation |

### Routing Guidance

- **DeepSeek v4 Flash** is the default scout and tester. It has a 1M context window and is cheaper. Use `--thinking off` for deterministic log triage.
- **Kimi k2.6** is the default scribe. Its output is more polished for docs and release notes. Enable thinking for ambiguous summarization; disable for structured extraction.
- **DeepSeek v4 Pro** is the narrow-coder escalation when the task is simple and repo-grounded but too large for a scout report. Do not use it for architecture decisions.
- Always verify names before shipping with: `pi --list-models <provider>`.

## Limitations, Risks, and Safe Defaults

### Known Limitations

1. **No native JSON output contract.** pi-agent returns plain text / markdown. AgentTeam must parse the text output or ask the agent to emit structured artifacts (task.json, result.json) inside the run directory.
2. **No built-in cost tracking.** pi-agent does not report token usage or cost in the CLI output. AgentTeam should record start/end timestamps and estimate cost from model tier.
3. **No automatic worktree creation.** Unlike Codex or Claude Code, pi-agent does not manage git worktrees. AgentTeam (or a wrapper script) must create the worktree before invoking a write-capable pi-agent role.
4. **Session resume requires matching `--session-dir`.** If the dir path changes between invocations, `--continue` will not find the session.
5. **Tool allowlist is not sandboxed.** `--tools` is advisory; a misconfigured invocation could still allow destructive commands if `bash` is enabled.

### Safe Defaults

- **Default mode:** read-only scout (`--tools read,grep,find,ls`).
- **No bash by default.** Enable `bash` only for tester roles with known safe commands.
- **No edit/write by default.** Enable `edit,write` only inside an isolated worktree with an explicit approval gate.
- **Always use `--session-dir`.** Never let pi-agent write sessions to the global default where they could collide.
- **Always quote the task packet.** The prompt is positional and must be the last argument.
- **Escalation rule:** before upgrading from `deepseek-v4-flash` to `deepseek-v4-pro` or `kimi-k2.6`, the agent must record a reason in `decisions.md`.

## How AgentTeam Should Parse / Import pi-agent Output in Phase 6

Because pi-agent returns plain text in non-interactive mode, AgentTeam should adopt a **structured-artifact convention**: instruct the pi-agent to write its deliverables into the run directory, then AgentTeam reads those files.

### Import Contract

After spawning pi-agent, the adapter should:

1. **Wait for exit.** Capture stdout/stderr as a fallback log.
2. **Read run artifacts.** Look for:
   - `.agentteam/runs/<run-id>/summary.md`
   - `.agentteam/runs/<run-id>/result.json`
   - `.agentteam/runs/<run-id>/evidence.md`
   - `.agentteam/runs/<run-id>/blockers.md`
3. **Map to delegated_run record:**
   - `status`: parse `result.json` → `"completed"`, `"failed"`, or `"blocked"`.
   - `progress`: parse `heartbeat.json` → `progress` field, default to 100 on completion.
   - `current_step`: from `heartbeat.json` or `summary.md` first heading.
   - `evidence`: array of artifact file paths plus any command outputs.
   - `changedFiles`: from `result.json` `changedFiles` array.
4. **Emit activity events:**
   - `command_run` / `command_result` for each command in `result.json`.
   - `file_changed` for each file in `result.json`.
   - `reasoning` for decisions recorded in `decisions.md`.
5. **Create inbox items if blockers exist:**
   - If `blockers.md` is non-empty, create an `inbox_items` row with type `"agent_blocked"`.

### Fallback Parsing

If structured artifacts are missing, the adapter should:
- Treat stdout as the summary.
- Set `status` to `"completed"` if exit code is 0, else `"failed"`.
- Set `changedFiles` to an empty array (unknown).
- Log a warning that artifact import was degraded.

### Example Task Packet Convention

AgentTeam should wrap every pi-agent invocation with a standard preamble that instructs the agent to produce artifacts:

```text
You are a <role> for AgentTeam Phase 6.
Your run ID is <run-id>.
Work inside <worktree> (branch <branch>).
Write scope: <files>.
Before starting, read relevant memory and confirm scope.
During work, update heartbeat.json and progress.md at milestones.
When blocked, write blockers.md and set heartbeat status to "blocked".
When done, write summary.md and result.json.
Result.json must contain: status, changedFiles, commandsRun, validation, blockers, followUps, recommendedNextAgent.
```

This convention makes pi-agent behave like any other adapter (Claude Code, Codex) from AgentTeam’s perspective.
